"Tell vs Feel" is an A/B test on the free reading speed test at readsharp.app/reading-speed-test. The flag is `speed_test_next_step`, with `tell` as the control and `feel` as the variant.

Visitors enter only after pressing Start. The page excludes visitors with Global Privacy Control (GPC), `?optout`, or a European, `UTC`, `Etc`, or unknown time zone.

## 1. Privacy copy

The page makes a random UUID in memory for one page view and uses it as a transient identity. It sets no cookies and uses no browser storage. The SDK uses an in-memory storage adapter.

Each event carries the random ID, the version shown, the event name and a timestamp. The events are `$flag_exposure` (at the result), `get_readsharp`, `result_shared`, `installer_download`, `send_to_pc`, and `feel_read_finished`. The page never sends reading speed or answers.

Flagsmith is the testing service. The browser connects to it directly, without a proxy, so Flagsmith receives the visitor's IP address with the requests. Cloudflare hosts the site and may keep standard server logs, as today.

Flagsmith publishes no fixed retention period for identities, transient identities, experiment events or request logs. Its policy says it keeps personal information "as long as reasonably necessary". Its docs say transient identities avoid "long-lived storage in the platform". [Flagsmith privacy policy](https://www.flagsmith.com/privacy-policy)

Turn on Global Privacy Control to opt out on every visit. `?optout` covers one page view. Browsers set to a European time zone are never included. The random ID lasts one page view, so it cannot be linked to the visitor later.

Flagsmith documents no identity-deletion tool. Send deletion requests to privacy@flagsmith.com.

Not legal advice.

## 3. Fallback if transient identities miss the results

In Development, the edge API accepted transient identities (HTTP 200) and reported them in the experiment (`in_experiment: true` for 30/30). The A2 Development proof gate checks whether those visitors appear in the Flagsmith experiment results.

Update from the overnight run: they already do. After the local browser tests, the Development results for experiment 958 showed 84 transient browser identities (38 `feel`, 46 `control`) with their `get_readsharp`, `result_shared` and `installer_download` conversions, a few minutes after they were sent. A2 still repeats the check on the deployed preview, so the fallback is unlikely to be needed.

The fallback uses a persistent random ID. The page still makes a fresh random UUID per page view and holds it only in memory. One option in `web/experiment.js` changes so the request omits `transient=true`. Flagsmith then stores the random identity with the version shown.

Disclosure (e) changes to

> "... sends Flagsmith, our testing service, a random ID made for this visit, which Flagsmith keeps with the version you see, which result buttons you press, whether the sample reader finishes, and when. ..."

The privacy section adds

> "Flagsmith stores that random ID with the version shown and the events; it is not linked to you."

To switch to the fallback (only after the item 6 proof gate has failed for 30 minutes):

1. In the ReadSharp worktree, add `transient: false` to the one `createExperiment({ ... })` call in `site/experiment/entry.js` (that private file is what the build bundles; `web/experiment.js` already supports the option).
2. Apply the fallback copy above to the disclosure in `scripts/build-site.mjs`, the privacy-page section, and `PRIVACY.md`.
3. Rebuild with the Development key and redeploy the preview (item 6, Step A).
4. Rerun the suite with `$env:E2E_EXPECT_TRANSIENT = "0"` (it then expects identity requests without `transient=true`), and run the proof gate again with a new before snapshot.

**Default** Use the fallback only if the proof gate fails.

## 4. Privacy model

Disclosed opt-out includes eligible visitors who press Start. GPC, `?optout`, and European time zones are excluded, and the speed test disclosure and privacy page explain the test.

Opt-in for everyone is the strictest option. It puts a checkbox before Start and costs most of an already small sample. At 300 visitors per arm, only an observed gain of about 4.3 points reaches 95%.

Not legal advice.

**Default** Keep disclosed opt-out as built. If no, A2 builds opt-in.

**Decide: keep disclosed opt-out (yes/no)**

## 5. Feel reader playback

Autoplay plays once when the reader is at least 60% visible. Users who prefer reduced motion always get a Play button. Pause/Play is always available, and playback pauses in hidden tabs.

Autoplay draws attention, a stated limitation of the test (a confound). Click-to-play takes one argument change (`autoplay: false`), and fewer visitors would feel the pace. The test never changes its playback setting automatically.

**Default** Keep autoplay.

**Decide: keep autoplay (yes/no)**

3. The proof gate, per arm. The suite writes `test-results/e2e-counts.json` with the sessions that reached a result and the Get ReadSharp clicks, by arm (it clicks in every one of its 20 "(h)" sessions, so both arms get clicks). A few minutes later (Development processed new events within about 5 minutes overnight):

```powershell
node scripts/proof-gate.mjs check docs/proof/before.json test-results/e2e-counts.json
```

It passes only if, in each arm separately, exposures grew by at least that arm's sessions and `get_readsharp` by at least that arm's clicks; one arm's growth can't cover the other's. It saves `docs/proof/before.after.json` as the evidence. On FAIL, run the check again every 5 minutes (Flagsmith refreshes results at most that often). If neither passes by the track checkpoint (1.5 h after A2 starts), stop and decide on the track checkpoint (plan section 2).
